3. The startup version log should handle the import-error case.
importlib.metadata.version("biomapper") is the right call, but it raises PackageNotFoundError if the package is somehow unavailable (e.g. dev environment where it's installed from a local path without metadata). Make the log line defensive:
python# at startup
try:
    from importlib.metadata import version
    biomapper_version = version("biomapper")
except Exception as e:
    biomapper_version = f"unknown ({e})"
logger.info("biomapper version: %s", biomapper_version)
Trivial but prevents the startup log line itself from becoming a source of crashes during the rename transition.
4. Smoke test should also verify no ddharmon import succeeds.
After the rename, attempting import ddharmon should fail with ModuleNotFoundError. That's a cheap one-line verification that the old package is genuinely gone from the environment, not just unreferenced:

(6) Additionally verify: python -c "import ddharmon" fails with ModuleNotFoundError. If it succeeds, ddharmon is still installed from a prior pip install and should be uninstalled (pip uninstall ddharmon) so nothing can accidentally fall back to it.

This catches the scenario where the requirements.txt was updated and biomapper was installed, but ddharmon was never uninstalled — imports still resolve from the old package, and the "rename" was a no-op.
